# Архитектура

## Текущая (v0.1)

```
┌───────────────────────────┐      HTTPS (rustls)       ┌──────────────────┐
│ opencode_old_macos (CLI)  │ ─────────────────────────▶ │ OpenAI-совместимый│
│ Rust, один бинарник,      │    POST /chat/completions  │ API (OpenAI,     │
│ тонет на macOS 10.13+     │                            │ vLLM, Ollama,    │
└───────────────────────────┘                            │ гейтвей)         │
                                                         └──────────────────┘
```

Принципы, из-за которых это работает на старых macOS:

- **Один автономный бинарник.** Никаких внешних рантаймов (Node/Bun/Electron).
- **TLS в stdlib (rustls).** Не зависит от системного OpenSSL/секуритариев ОС.
- **TUI — ANSI/stdio.** Не нужны системные веб-движки (WebKit/Chromium).
- **Deployment target задаётся на компиляции** и проверяется CI по `LC_BUILD_VERSION`.

## Целевая (энтерпрайз-слой)

Политики и контроль прав не должны жить в CLI (который работает на хрупких старых
машинах). Они живут на серверной стороне — **policy-гейтей**, через который клиент ходит
к моделям.

```
┌─────────────────┐   ┌──────────────────────────────────────────────┐   ┌──────────────┐
│  CLI (Rust,     │   │  Policy Gateway (modern servers)              │   │ LLM providers │
│  старый macOS)  │──▶│  ─ депозит запрос, единый контракт            │──▶│ OpenAI/       │
│                 │   │  ─ аутентификация: доменный IdP               │   │ Anthropic/    │
│  Web/IDE,       │   │    (Keycloak/OIDC, SAML, LDAP/AD)             │   │ локальные     │
│  cron/CI        │   │  ─ авторизация: политики (RBAC/ABAC)          │   │ vLLM и т.д.   │
└─────────────────┘   │  ─ лимиты/квоты, задержки, баджеты            │   └──────────────┘
                      │  ─ аудит-лог (кто, что, когда, во сколько)     │
                      └──────────────────────────────────────────────┘
```

Зачем так:

- Политики применяются централизованно — их нельзя обойти старым/сломанным клиентом.
- Аудит и лимиты едины для CLI, web, CI-агентов и IDE-плагинов.
- CLI остаётся «тощим» и портируемым; тяжёлая логика — там, где современные ОС.

### Что нефункциональных требований закладываем с первого дня

- **`tracing` + события аудита** как структурные логи (JSON), разделение «события
  продукта» и «диагностика».
- **Конфиг с версионированием** — чтобы в будущем подложить удалённые политики без
  миграции формата.
- **Изоляция провайдеров за интерфейсом** (`trait Provider`) — чтобы войти за гейтвей
  или любой OpenAI-совместимый сервер без переписывания клиента.

```
  main.rs       точка входа, разбор CLI
  config.rs     конфиг (CLI > env > .env > default)
  api.rs        HTTP-клиент /chat/completions (v0.1 — не потоковый)
script/
  check-minos.sh  проверка минимальной macOS бинарника (CI)
.github/workflows/
  ci.yml          сборка + тесты + darwin-x64 + minOS-чек
```
